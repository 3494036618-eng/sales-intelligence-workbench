# 销售智能工作台 Beta 发布与生产演进规划

## 1. 当前结论

当前版本是 `0.9.0` Beta，只支持单工作区、单人使用，以及本机或受控内网自托管。Cookbook 中的真实业务主链路已有代码和自动化验收支撑，身份认证、公开 DTO、持久化任务队列和独立 Worker 已补齐；成员邀请、角色管理、移动端、公网生产 SaaS 和 SLA 不属于当前发行范围。目标 Supabase 迁移目标为 `202607280002`，用于明确 OpenViking 与 Supabase 的问答数据职责边界，并把内部元数据表纳入 RLS 安全边界；付费预约和异步队列 smoke 均在事务中通过并回滚，备份包也已生成并通过校验。当前开发机已完成全 Provider 真实诊断及档案/问答验收，但在最终 URL 干净环境安装、备份独立恢复和开源授权确认前，仍不能公开发布 Beta，更不能宣称为公网生产平台。

历史测试环境已经真实验证的链路：

1. Codex CLI 调度飞书 CLI 读取当前用户有权限访问的飞书云文档。
2. 飞书资料按稳定来源标识增量导入；正文写入 OpenViking，Supabase 只保存来源、游标、内容指纹和业务索引，重复导入会按内容指纹跳过。
3. DataPro 解析真实企业主体并加入目标企业池。
4. DataPro、豆包搜索和模型共同生成带引用的最新档案，并持久化到 Supabase；OpenViking 和飞书资料不参与最新档案生成。
5. 资料问答仅使用 Supabase 档案与 OpenViking 召回的飞书资料，不额外联网；问答内容和长期上下文由 OpenViking Session 保存，Supabase 只保留会话索引。
6. 服务重启后，Supabase 可恢复销售目标、企业、档案和同步元数据，OpenViking 可恢复飞书资料正文与问答上下文。
7. Supabase 备份可生成并通过校验，恢复流程已完成只读预检。
8. 浏览器与 CLI 都要求个人账号会话；当前公开发行版的业务、付费 Provider 和运维接口仅对已登录用户开放。
9. 公开档案、资料和问答 DTO 不包含内部 URI、Provider 原始引用、密钥或运行诊断字段。
10. 连续问答会带入有界的历史上下文，同时仍只允许基于已保存证据回答。
11. 后端测试、Skill 生命周期自测、分发包一致性和受支持桌面浏览器布局检查均纳入验收。
12. 所有当前付费业务入口均建立 Job、Provider Run 和工作区级原子预约；业务 DTO 不返回 OpenViking 原始地址。
13. 档案证据具备来源分级、时效标记、关键数字冲突检测和高风险事实双来源校验；引用区展示业务化质量标签。

当前源码的离线自动化测试和发布校验已通过。2026-07-28 当前配置下，模型、DataPro、豆包搜索、OpenViking 和 Supabase 的真实诊断均通过；当前开发机也已使用全新企业完成主体搜索入池，并在浏览器跑通目标创建、档案生成、历史归档、资料问答、刷新持久化和目标切换隔离。发布前仍必须使用最终不可变 URL 在没有本项目历史配置的环境重新验证全部 Provider、Supabase 队列和浏览器主流程，不能把当前开发机结果当作干净环境结论。

### P1：首个稳定版本应完成

- 首次启动向导：逐项配置模型、DataPro、豆包搜索、OpenViking、Supabase 和飞书 CLI，并给出不泄密的可操作错误。
- 资料中心：查看来源、同步时间、增量游标、暂停/恢复/重试和删除影响，不要求用户使用命令行排障。
- 档案体验：引用侧栏、来源质量标签、资料截止时间、版本比较、变更摘要和一键复制。
- 任务中心：统一显示搜索、导入、档案、问答的状态、耗时、Token、费用估算和失败原因；普通销售不显示密钥或内部路径。
- 可访问性：键盘操作、焦点状态、语义标签、颜色对比度和屏幕阅读器检查。
- 可观测性：结构化日志、请求 ID、任务追踪、Provider 延迟/失败率/Token 指标和告警；日志默认脱敏。

## 4. 目标架构

```text
浏览器
  -> 身份认证与角色授权
  -> 同源业务 API
     -> 轻量读写请求
     -> 异步任务队列 -> Worker
        -> DataPro / 豆包搜索 / 模型
        -> 证据校验与事实安全层
        -> Supabase 企业、档案、任务与权限
     -> 飞书 CLI 受控导入
        -> OpenViking 资料正文
        -> Supabase 同步元数据
     -> 资料问答
        -> Supabase 当前档案
        -> OpenViking 资料召回与 Session 记忆
  -> 管理后台（独立权限）
     -> Provider 状态、任务、用量、审计、备份
```

公开业务 API 不返回密钥、内部 URI、完整提示词或 Provider 原文。所有付费调用都必须经过认证、授权、预算和幂等检查。

## 5. Beta 发布验收门槛

只有同时满足以下门槛，才能把版本标记为单工作区自托管 Beta；这些门槛不构成公网生产、多人协作或 SLA 承诺：

- 匿名请求访问业务、管理和付费接口均返回 `401`；越权访问返回 `403` 或不可枚举的 `404`。
- 跨 Workspace 的企业、资料、档案、问答和任务均无法读取或修改。
- 每条外部事实都能定位到可展示来源；高风险数字、经营判断和负面信息通过来源策略校验。
- 连续三轮资料问答能够正确继承上下文，且不会新增未保存的联网事实。
- 任一 Provider 超时、限流或不可用时，任务有明确状态、可安全重试，且不会重复写入。
- 1280px、1440px 等受支持桌面视口无横向溢出，核心流程可仅用键盘完成；移动端不属于当前 Beta 验收范围。
- 服务重启、数据库迁移、备份、独立目标恢复和版本回滚均通过演练。
- 全新机器从克隆仓库到完成配置、导入资料、生成档案和问答，有可复现的自动化验收记录。
- 密钥扫描、依赖/许可证检查、单元测试、集成测试和浏览器端到端测试全部通过。
